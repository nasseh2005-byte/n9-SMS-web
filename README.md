# N9 SMS Web

واجهة عربية لإدارة أرشيفات SMS، فصل رسائل الشركات، البحث والمطابقة من Excel، إنشاء رسائل يدوية، وتحديد الأدلة وتصديرها كصور أو ملفات PDF بأسماء مستخرجة من أرقام الرسالة وبثيمات Android وHuawei وiPhone. ويمكن تصدير المحادثة المفتوحة كاملة: PDF مستقل لكل رسالة وملف Excel مرجعي داخل ZIP واحد، مع نسبة إنجاز ظاهرة أثناء العمل.

تفتح واجهتا الترحيب والتطبيق بالثيم الفاتح، ويبدأ اسم المستخدم فارغاً مع زر واضح للعودة من تسجيل الدخول. وضع المطابقة الافتراضي يدوي؛ لا يُعتمد دليل ولا يتفعّل تصدير نتائج المطابقة حتى يختار المستخدم الرسالة، إلا إذا فعّل وضع الاقتراح التلقائي صراحةً. تصدير المحادثة الكاملة مستقل عن هذا الاختيار ويشمل كل رسائل المحادثة المفتوحة.

الهوية الداخلية والخارجية موحدة: لؤلؤي عاجي بلمسات ذهبية في الوضع الفاتح، وكحلي عميق بنيون أزرق في الوضع الليلي. يتبدل شعار N9 تلقائياً بين نسختيه، ويظهر شعار المنتج نفسه كأيقونة للمتصفح، دون تغيير شاشة الهاتف أو دليل الرسالة أو لقطة التصدير.

## النشر على Vercel

المستودع مجهز للاستيراد المباشر من GitHub إلى Vercel:

1. افتح **Add New → Project** في Vercel واستورد `nasseh2005-byte/n9-SMS-web`.
2. من **Storage / Marketplace** اربط قاعدة Neon Postgres بالمشروع؛ سيصل التطبيق إلى `DATABASE_URL`.
3. أنشئ Vercel Blob بوصول **Private** واربطه بالمشروع؛ سيصل التطبيق إلى `BLOB_READ_WRITE_TOKEN` أو بيانات OIDC الخاصة بالمتجر.
4. أضف متغيراً سرياً خاصاً بالخادم باسم `BOOTSTRAP_ADMIN_PASSWORD` وقيمته الرقمية المطلوبة لأول مدير (مثلاً `2005`). لا تضف بادئة `VITE_` ولا تضعه في GitHub.
5. اترك إعدادات البناء من `vercel.json` كما هي ثم أعد النشر.

يستخدم Vercel الأمر `npm run build:vercel`، وينشر الواجهة من `dist/client` وواجهة API الخادمية من `api/index.js` تلقائياً.

### وضع البيانات على Vercel

نسخة Vercel تعمل بوضع سحابي مشترك:

- الحسابات والجلسات والشركات والصلاحيات محفوظة في Neon Postgres، لذلك تظهر للمستخدم المصرح من أي جهاز.
- أرشيف كل شركة محفوظ ككائن JSON خاص في Vercel Blob، ولا يصل إليه المتصفح إلا برابط قصير العمر بعد التحقق من الجلسة وصلاحية الشركة.
- الرفع الكبير ينتقل مباشرة إلى Blob ثم يتحقق الخادم من حجمه وبنيته قبل اعتماده، مع حماية من الكتابة المتزامنة من جهازين.
- وضع IndexedDB باقٍ للتطوير المحلي فقط (`npm run dev`) ولا يمثل بيانات Vercel.

بعد تفعيل الخدمات لأول مرة يكون الدخول الأول باسم `nasseh` وبقيمة `BOOTSTRAP_ADMIN_PASSWORD`. الحسابات والأرشيفات التي كانت محفوظة سابقاً داخل IndexedDB لمتصفح واحد لا تنتقل تلقائياً إلى السحابة؛ أعد إنشاء المستخدمين وارفع ملف XML مرة واحدة، وبعدها تتزامن البيانات على الأجهزة.

إذا ظهر تنبيه عن عدم ربط Neon أو Blob فالمشكلة في متغيرات مشروع Vercel، وليس في XML؛ اربط الخدمة بالبيئات المطلوبة ثم نفّذ **Redeploy**.

لا تجعل مستودعاً يحوي بيانات عملاء أو ملفات XML حقيقية عاماً. ملفات XML وPDF الأصلية ليست مضمنة في هذا المستودع.

المستودع الحالي ظاهر للعامة. أبقِ فيه كود التطبيق والبيانات التجريبية فقط، وغيّر ظهوره إلى **Private** قبل إضافة أي ملف عمل حقيقي أو إعداد سري.
